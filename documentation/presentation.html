PROJECT OVERVIEW

Why Microservices Instead of One Big App?

Easy Comparison Between Traditional Monolithic Systems and AeroBook Microservices

Traditional Monolith (One Big App)

  • • Single Point of Failure: Everything is inside one program. If one small feature crashes, the whole website stops working.
  • • Shared Database Slowdowns: All features share one database. When thousands search for flights, it slows down logins and payments.
  • • Hard to Update: Even a tiny bug fix requires stopping and restarting the entire system.
  • • Difficult Teamwork: Multiple developers working on one giant codebase causes code conflicts.

AeroBook Microservices (Our Approach)

  • • Independent Services: Divided into small separate services. If check-in is busy, flight search and booking still run smoothly.
  • • Separate Databases: Each service has its own private database, so search traffic does not lock up booking tables.
  • • Easy Updates: We can update or fix one service without shutting down the other services.
  • • Fast and Scalable: If flight bookings spike during holidays, we can easily run extra copies of just the booking service.
Modular Design • Independent Databases • Zero-Downtime Updates
SYSTEM ARCHITECTURE

The Core Microservices in AeroBook

Each Service Does Exactly One Job Well (Simple & Modular)

1. API Gateway Port 8083 • Main Entrance

Front door for all requests; automatically sends requests to the right service.

2. Service Discovery Port 8761 • The Phonebook

Netflix Eureka keeps a live list of all running microservices automatically.

3. Auth Service Port 8082 • Security

Handles user registration, password encryption (BCrypt), and login tokens (JWT).

4. User Service Port 8084 • Profiles

Stores customer details like name, email, phone number, and nationality.

5. Flight Service Port 8087 • Schedules

Manages airplanes, flight schedules, departure times, and available seats.

6. Fare Service Port 8089 • Pricing

Calculates Economy, Business, and First Class ticket prices plus taxes.

7. Booking Service Port 8088 • Reservations

Creates flight bookings, saves passenger details, and generates PNR codes.

8. Check-In Service Port 8090 • Boarding

Lets passengers choose their seat (e.g. 12A) and get a digital boarding pass.

8 Microservices • Clean Separation of Responsibilities • Port-Mapped
WORKFLOW

How AeroBook Works: Step-by-Step

A Simple Walkthrough of the Customer Journey from Search to Boarding Pass

Step 1: Search Flights

Passenger enters origin city, destination, and travel date. System displays all available flights with live ticket prices.

Step 2: Select & Add Passengers

Passenger picks a flight, selects Economy or Business class, and enters passenger names and ages.

Step 3: Safe Seat Reservation

Flight Service safely checks and decrements available seats so two people cannot buy the same seat at once.

Step 4: Instant PNR Generation

Booking Service creates the reservation, confirms the ticket, and generates a unique PNR code (e.g. PNR-AB789).

Step 5: Web Check-In (T-24h)

Within 24 hours of flight departure, passenger enters PNR and chooses their favorite seat (e.g. 12A).

Step 6: Digital QR Boarding Pass

Check-In Service assigns the seat and immediately creates a digital boarding pass with a QR code for airport gates.

Simple User Flow • Real-Time Seat Validation • Digital Mobile Boarding
